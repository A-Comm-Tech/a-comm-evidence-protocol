# Per-PSP evidence paths (informative)

Draft for spec Appendix C, raised in issue #105. Informative only: it changes no normative text, field, hash or signature rule. Maintainers may move it into Appendix C or keep it here as working-group guidance.

This table records how each PSP's public documentation says a merchant submits dispute evidence, as read on the date shown. "Not documented" means the linked page was read and names nothing; it is not a claim that the capability does not exist. Rows appear only where a primary source is cited. Order is not a ranking.

| PSP | Documented evidence path | Primary source | As of |
|---|---|---|---|
| Stripe | Structured Visa CE 3.0 object on the Update Dispute call: `evidence.enhanced_evidence.visa_compelling_evidence_3`, with `disputed_transaction` and `prior_undisputed_transactions` (`customer_device_id`, `customer_device_fingerprint`, `customer_purchase_ip`, `customer_account_id`, `customer_email_address`, `shipping_address`, `product_description`; `merchandise_or_services` on the disputed transaction only). Other artifacts ride in text and file evidence fields such as `uncategorized_text` and `uncategorized_file`. Combined text limit 150,000 characters; the long text fields are also capped at 20,000 each. No agent, login ID or device-owner parameter is documented. | https://docs.stripe.com/disputes/api/visa-ce3 and https://docs.stripe.com/api/disputes/update (API version 2026-10-28.endive) | 2026-11-10 |
| Braintree | Text evidence by category, including `DEVICE_ID`, `PURCHASER_IP_ADDRESS`, `PURCHASER_EMAIL_ADDRESS` and the `PRIOR_NON_DISPUTED_TRANSACTION_*` set. File evidence by category, including `PROOF_OF_AUTHORIZED_SIGNER`, `SIGNED_ORDER_FORM` and `MERCHANT_WEBSITE_OR_APP_ACCESS`. Neither page names Visa CE 3.0. No agent category is documented. | https://developer.paypal.com/braintree/docs/reference/request/dispute/add-text-evidence and https://developer.paypal.com/braintree/docs/reference/request/dispute/add-file-evidence | 2026-11-10 |
| Adyen | Defense documents uploaded through the Disputes API `/supplyDefenseDocument` call as PDF, JPG or TIFF, each with a `defenseDocumentTypeCode`. Not sent to the issuer until the defend call. The Help Center FAQ routes Visa CE 3.0 data through the Adyen Support Team; no structured CE 3.0 field is documented on the API page. | https://docs.adyen.com/risk-management/disputes-api and https://help.adyen.com/knowledge/risk/dispute-management/faqs-visa-compelling-evidence-3 | 2026-11-10 |
| Checkout.com | Paired text and file evidence fields on the Disputes API, for example `additional_evidence_text` and `additional_evidence_file`, `invoice_or_receipt_text` and `invoice_or_receipt_file`. Text fields are limited to 500 characters. No structured CE 3.0 object and no agent field are documented on the page. | https://www.checkout.com/docs/risk-management/disputes/disputes-api | 2026-11-10 |
| PayPal (wallet disputes) | `POST /v1/customer/disputes/{id}/provide-evidence` with typed evidence entries (the schema lists `PROOF_OF_FULFILLMENT`, `ORDER_DETAILS`, `PERMISSION_DESCRIPTION`, `BILLING_AGREEMENT` and `PROOF_OF_RECEIPT_COPY` among the types) and a `notes` field. No AI agent field is in the schema. | https://developer.paypal.com/docs/api/customer-disputes/v1/ and https://developer.paypal.com/api/customer-disputes/v1/schema.json (version 1.12) | 2026-11-10 |

## Scope of this draft

Five PSPs, each read on its own public docs on the date shown. Other PSPs are left out until someone cites a primary source for them. Corrections with a newer primary source are welcome as edits to the row and its date.
